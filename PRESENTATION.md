## Three-minute full-workflow route

The [published narrated video](https://ian18858863.github.io/redline-referee/demo.mp4) is available for the existing negotiation workflow. It uses authored cases with recorded real API responses; it does not show the new SEC case.

1. **Quiet changes:** show the cover-note assurance beside the 30-to-90-day payment change. Follow the page evidence, the two readers, the playbook passage and the counter route.
2. **Two readers:** show a semantic disagreement that remains held, then a faithful rewording that clears. Explain what each reader changes in the outcome.
3. **Guard and document gate:** show the note addressed to an AI reviewer, then the unrelated-file case. Explain why these stop a pass.
4. **Reviewer action:** show the proposed reply and sentence checks. Prepare the internal handoff; the reviewer copies and sends it.
5. **Evidence:** show the endpoint audit and the external-source results. Name the evaluation scope when quoting a number.

## Closing line

“Redline Referee connects the contract, the explanation, the policy and the next action. Every important decision should come with a passage you can inspect and an owner who can act.”

## Presenter checks

- Open the exact build being presented and inspect the real case before recording. Use its actual displayed result.
- Call the SEC example a **real public-contract excerpt comparison**. It is neither a fabricated contract nor a full-contract accuracy benchmark.
- Use the eight-pair and ten-case denominators beside evaluation figures. Replay speed is not live API latency.
- If asked about user validation: “The technical evaluations are reproducible. A paired study with intended users is the next validation step; zero participants have completed it, so we make no measured time-saving claim.”
- A strong vision is appropriate: faster, more consistent review with traceable decisions. Do not turn that ambition into an observed productivity or legal-outcome figure.
